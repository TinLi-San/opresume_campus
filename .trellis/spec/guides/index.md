# 开发思维指南

> **目的**：扩展你的思维，捕捉可能忽略的问题

---

## 为什么需要思维指南？

**大多数 bug 和技术债务来自"没想到"，而不是技能不足**：

- 没想到层级边界会发生什么 → 跨层 bug
- 没想到代码模式重复 → 到处都是重复代码
- 没想到边界情况 → 运行时错误
- 没想到未来的维护者 → 不可读的代码

这些指南帮助你**在编码前提出正确的问题**。

## 快速参考：思维触发器

### 何时思考跨层问题

- [ ] 功能涉及 3+ 个层级（API、Service、Component、Database）
- [ ] 数据格式在层级间变化
- [ ] 多个消费者需要相同数据
- [ ] 你不确定某些逻辑应该放在哪里

→ 阅读 [跨层思维指南](./cross-layer-thinking-guide.md)

### 何时思考代码复用

- [ ] 你正在编写与现有代码类似的代码
- [ ] 你看到相同模式重复 3+ 次
- [ ] 你正在多个地方添加新字段
- [ ] **你正在修改任何常量或配置**
- [ ] **你正在创建新的工具/辅助函数** ← 先搜索！

→ 阅读 [代码复用思维指南](./code-reuse-thinking-guide.md)

## 修改前规则（关键）

> **在修改任何值之前，务必先搜索！**

```bash
# 搜索你要修改的值
rg "要修改的值"
```

这个习惯可以防止大多数"忘记更新 X"的 bug。

---

## 如何使用此目录

1. **编码前**：浏览相关的思维指南
2. **编码中**：如果某事感觉重复或复杂，查看指南
3. **修复 bug 后**：将新的见解添加到相关指南（从错误中学习）
